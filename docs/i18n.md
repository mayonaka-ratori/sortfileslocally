# Internationalization (i18n) Guide

LocalCurator Prime uses `next-intl` for localization, supporting both server and client-side translation.

## How it works

1. **Message Files**: All translations are stored in `web/messages/[locale].json`.
2. **Provider**: The `web/src/components/I18nProvider.tsx` handles locale selection and dynamic loading of message files on the client side.
3. **Locale Selection**: The app priority is: `localStorage.getItem('locale')` -> Browser preference -> Fallback (`en`).
4. **Usage**: Use the `useTranslations` hook from `next-intl`.

## Adding a New Language (e.g., Korean)

Follow these steps to add support for a new locale:

1. **Create Message File**:
   Copy `web/messages/en.json` to `web/messages/ko.json` and translate all values.

   ```bash
   cp web/messages/en.json web/messages/ko.json
   ```

2. **Add to Language Selector**:
   Update `web/src/components/LanguageSelector.tsx` to include the brand new option in the list.

   ```tsx
   const languages = [
       { code: 'en', name: 'English', flag: '🇺🇸' },
       { code: 'ja', name: '日本語', flag: '🇯🇵' },
       { code: 'ko', name: '한국어', flag: '🇰🇷' }, // Add this
   ];
   ```

3. **Verify Provider**:
   The `I18nProvider.tsx` dynamically imports the json based on the code, so it will automatically work as long as the file exists and the code matches.

4. **Update Type Definitions (Optional)**:
   Ensure any locale-specific logic (like date formatting) accounts for the new locale.

## Adding Translation Keys

**CRITICAL**: When adding a new key, you MUST add it to BOTH `en.json` and `ja.json` (and any other supported languages). Failure to do so will result in `missing key` warnings in the UI.

### Naming Convention

We use a hierarchical namespace system:
`namespace.category.key`

Example:

```json
{
  "setup": {
    "welcome": {
      "title": "Welcome to LocalCurator Prime",
      "desc": "Organize your local media library using local-only AI."
    }
  }
}
```

## Testing Translations

1. **Linting**: Run `npm run lint` in the `web` directory. It checks for structural consistency in some configurations (if configured).
2. **Visual Check**: Switch the language in the app settings or setup wizard to verify text fits within UI boundaries.
3. **Key Count**: Use a script to verify that all json files in `web/messages/` have the same set of keys.
